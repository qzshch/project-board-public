# 可直接交给整理 Worker

你作为本项目的历史整理Worker，使用自己的项目身份。项目ID、整理时间段、允许读取的目录/会话由SE在派发时给出；先读 /help/retrospective，下载 /retrospective-kit.zip。

1. 读取本项目当前任务、原生Session目录、已有用量和工时，保留原任务ID及历史范围。只读明确授权的项目来源，不扫描账号全部会话。
2. 列出已有记录、可证明的缺口、重复/冲突及无法归因的内容。已有用量只引用，不换ID再导入。Token明确逐调用或累计差值；缺累计基线保持未知。工时仅录有依据的有效投入，不把会话历时当工时。
3. 原件留本地/server，生成本项目MANIFEST.json，记录原生Session ID、来源位置/机器/SHA、时间段、任务与历史范围、分类依据、缺失清单和保留规则。不复制密钥/私有身份或无关项目材料，不删除或搬迁原件，不把原件加入Git。
4. 按模板生成 project_id + draft 整理包；每批最多64条补录。大量已有材料放清单入口，entries可空。已存在记录与无法可靠归因的历史在summary/missing说明，不重复登记。
5. 使用工具核对本机明确目录内的来源摘要并生成冻结请求，以本人身份提交 /api/retrospectives。只提交草案，不冒充SE审核，不改变原任务状态、依赖和验收。遇到冲突留言说明，不能换ID绕过去重。
6. 把批次ID、版本、归档清单入口和缺失摘要回到任务中。记录本次整理工作的实际工时和用量；无需把同一报告再复制到多个地方。

需要修订时沿用同一批次ID并递增version；已入账用量保留条目ID、会话、区间、任务和范围，修正计数并解释依据。旧核定版本继续生效，直至SE核定新版本。
