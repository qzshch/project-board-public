# 原范围收口：接续联通、完整入口、条件图与操作减负

基线1f83d469dd3d7ea5f1e8e0ef1b2c54cc59ae4206。仅处理核对发现的遗漏和重复操作，不增加预算、调度、Agent托管或其他治理模块。沿用现有项目ID、四条追加链、权限与server部署。新动作增量加入operations；旧单项动作和任务负责人最终交付权限保留。

- 授权尝试参与者：有效租约下登记本人检查点、进展、阻塞和作业时间；不因此获得任务最终submit、验收或管理权限。接续按参与者/尝试区分，工作台能找到本人参与的活跃任务。失联仍保留占用，旧租约不得回写有效执行结果。
- 接手包：包含显式引用的materials与entries，按位置去重并保留类型、版本和摘要；分页入口和截断原因明确。增量消息可按任务及其前置过滤，同时保留有标识的项目公共边界变化。
- 条件图：现有依赖图加入当前条件门及状态，条件边与硬任务依赖分开。入口仍按项目权限；停用/旧范围条件不当作当前前置，不改变实际门禁计算。
- 当前工作台：已完成任务的旧条件/实施计划不生成当前行动；已结束回退进入折叠历史。当前任务的未解决问题、待恢复尝试和阻塞继续显示。
- 操作减负：关联草案/转任务使用字段编辑器，JSON为高级入口；验收项可显式选择后批量声明/审核，逐项保留结论、声明ID与相同输入的证据，事务中任一项失效则整批不写入。Git阶段记录允许在同一精确输入上按选择批量核验，阶段语义及最终运行门禁不变。不自动批准或跳过审核。
- 新规划可按研究成果与范围而非说明性事件revision追踪前置，保留旧审批计算方式，采用新跟踪方式须明确的新模块版本与研究决策。成果/范围/状态改变仍使结论失效。
- 手册重排一次性轻量任务、同类规则复用、跨会话/多路尝试、高风险完整路径；解释评论、需求、评审发现的使用边界。未采用机制默认折叠，不迫使所有任务走完整流程。

验收使用独立HTTP/Git fixture，覆盖两个真实不同的项目Actor并行、越权/过期/旧选择、批量中途失败回滚、入口裁剪/分页/跨项目、条件图、历史过滤、说明性变动不误伤而成果变化失效，以及桌面1280/手机375/浅深色实际渲染。测试与原件不进Git。server固定提交完整回归、备份、源码回滚、三服务重启及原身份/四链前缀读回后交付；不在生产创建演练数据。
