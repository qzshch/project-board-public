# 产品工作空间 v2

从左侧进入项目概览、产品管理、工程交付、协作与资源、分析与设置。
项目身份、原任务动作和验收门禁保持。人类账号可切换全部项目；Agent只使用本项目身份。
旧入口参数继续有效，旧“需求与改进”位于“历史发现与改进”。

## 最短路径

1. 人类或Worker在“需求池”记录标题和想法；无需先拆任务，也不自动承诺。
2. SE补充用户情境、结果、范围、非目标、负责人和稳定ID验收项，再确认定义。
3. 是否排期是独立决定。关联已有任务时核对当前范围摘要；任务仍按原流程执行。
4. 已确认定义不能直接覆盖。提出变更，核对差异、直接/传递任务影响、接口、测试、
   资产和里程碑迁移，批准新版本。受影响任务显示“待工程核定”，不得假装已改范围。
5. 任务验收后，SE对每条需求标准登记业务验证证据。任务完成不会自动宣布需求达成。

“暂缓、不采纳、重复、归档”记录理由。重复不得成环。尚无明确结果不能直接归档。
历史 intake 保留原ID和处置；点击“采用产品管理”后从待核定状态开始，旧结论保留，
不会补造验收。采用后的记录不能再用旧 intake_decide/convert 绕过新门禁。

## 缺陷

信息不全可先登记。严重度与处理优先级独立。确认前补充实际/预期、环境、发现版本和步骤。
关联修复任务后，复测必须指向精确修复输入、当前任务范围、实际环境、用例运行和证据。
修复任务提交不会关闭缺陷，原finding也不会随缺陷关闭。失败或复现可重开，所有轮次保留。
finding_promote 可把跨任务问题提升一次；重复调用返回同一缺陷，不改变原评审门禁。
“非缺陷/不修复”是独立处置，不是测试通过。

## Token用量与覆盖

“时间与效率”保留投入、等待、估算、WIP等内容，增加Token账本。
可按任务、模块、会话、执行者、需求、阶段、模型、来源和发生时间筛选并导出。
需求行可能消费同一任务，因此不能把需求行相加当项目总量。
总量只加 input + output；缓存读写是输入子集、推理是输出子集，不重复累加。
空任务需区分 attribution=project_overhead（SE项目协调）与unattributed（任务归因未知），不能把未归因都计为SE协调。
未知字段保留null；实测、导入、手填和估算分别展示，实测仅代表已采集下界。

采集需要先有本项目原生会话登记或受管绑定。节点只为本机受管绑定归因。
Codex已识别的 thread/tokenUsage/updated.total 通知进入本机持久队列，冻结样本后重试。
现有会话首次累计读数只作基线，不把历史全部算到当前项目。累计重置标异常，不能给负抵扣。
其他运行时未提供已识别用量时保持缺采样，可使用显式项目级规范记录导入；不扫描账号全部历史。

账本与operations全量状态分开追加。每条样本带原生会话、任务、阶段、模型、发生与接收时间、
本地来源文件位置和SHA256。相同actor/sample/revision精确重放；流式修订递增revision，重试调用用不同sample。
没有采集不显示为零；覆盖分母只包括平台已登记的项目会话，不代表账号总消耗。

## Agent原生会话目录

“Agent协作”和任务详情提供目录：完整原生Session ID、运行系统、机器、角色、模型、项目任务、
尝试、前序引用、状态和查找说明，可搜索、复制、导出。Codex记录thread ID，Zcode记录原生session ID，
Harness按其真实会话标识记录。绑定ID、传输任务ID和引用ID不能代替原生ID。
没有取得真实ID时明确未知；可登记外部会话，但这不使平台能够控制或恢复其他会话。
接续使用新引用ID并指向previous，原记录不可覆盖。普通任务不强迫建立执行尝试。

## 依赖与规模

图读取已授权项目的完整快照，支持模块总览、全图、模块与跨界节点、选中节点上下游、
关系类型、搜索、缩放、拖动、定位缩略图、键盘节点表和完整导出。模块框仅负责布局，
不是额外硬依赖。接口、共享修改、排他资源、产物和条件分别展示；条件按原适用阶段执行。
图不以“前100张”代替项目。节点表分批显示仅为阅读，导出与全图数据保留全部关系。
图的状态来自任务与门禁事实，点击任务仍使用原详情、领取、交付、评审和吸收流程。

## Agent API

先用本项目身份访问 `/api/projects/{project}/product`、`sessions`、`usage`。
产品和会话动作经原 `/operations` 接口，带request_id、expected_revision、action、payload。
产品更新另带id、expected_version；版本冲突先重读，不能静默重写旧请求。
主要动作：product_open/adopt/edit/confirm/schedule/change/change_decide/link/verify/dispose、
defect_retest/reopen、finding_promote、session_register。字段参考可下载模板。

用量通过 `/usage` POST，字段见 token-usage.json；不接收聊天、提示词和凭据。
导入工具：`python -m tools.usage_collector --profile <项目身份> --file <本项目规范JSONL>`。
身份、队列、原始通知和运行日志放Git外私有目录；server归档入口登记到项目资产。

由其他Worker整理历史时使用[事后整理与归档](/help/retrospective)，不要借用原执行者身份直接导入。Worker提交草案，SE核对后才进入原Token账本和历史工时统计，重复或无法证明不重叠的用量仅归档说明。修订保留原版本，批准补录不会自动验收任务或宣布时间完整。

Git接入见[代码与GitHub](/help/github)。旧框架、规则、里程碑、接口、测试、运行、
资产消费、回退和角色管理的完整字段与动作继续在原页面，不以本说明代替原手册。
