# 第一批协作与交付工作流冻结边界

delivery-workflow@1：项目内GET /workflow，GET /workflow/task?task=ID，GET /workflow/inbox；POST /operations复用request_id/expected_revision/action/payload，新增thread_*/criteria_*/review_*/git_check/rollback_*动作。工作流schema1，API2、治理2、operations1、Git1兼容。所有写入沿用项目SQLite BEGIN IMMEDIATE和operations追加链；任务/治理变更在同事务内追加对应原链，禁止覆盖历史。UTC秒，提交40hex、摘要64hex；错误400输入、403角色、404无权或不存在、409过期/条件不满足、413边界。

评论按线程记录普通讨论、阻塞、计划偏离和决策，支持回复、指定项目成员/SE、读取游标、已回复/待确认/解决状态。评论不改变任务scope或释放排他资源；阻塞线程阻止交付，正式变更需关联实际scope/contract事件。Worker仅处理本人任务的阻塞/偏离，其他项目成员可讨论；viewer/tracker/runner及回退执行器不得改开发协作。评论不是越权授权，旧范围线程须保留并重新核定。

验收计划固定任务scope_hash和scope_version、交付项、可判定标准及验证方式；执行者逐项声明，SE逐项记录结论。评审发现锚定文件/行/产物版本和验收项，修复与异议由执行者说明，审核者确认关闭；旧发现继续约束后续交付。范围或输入变化使旧声明/核验失效，历史任务不补造新验收。Git核验读取项目专属只读镜像，固定基线、实现、合入/运行提交及检查输入；检查实际路径和祖先关系，不以祖先关系代替精确输入测试。SE待办来自同一服务端规则，包括阻塞/偏离/未读、待审核及回退事项。

回退分任务成果撤回、模块方案恢复新版本、代码反向提交、固定资产消费和部署恢复；冻结当前范围/提交/影响、必需确认人及数据迁移处置，批准后由有权角色/独立受控执行器执行。代码反向提交在项目本地隔离工作区完成，GitHub追踪器保持只读；合并提交明确mainline，混合写集和数据迁移须显式方案。部署适配只执行本机管理员预先批准的固定目标和参数，不允许网页传任意命令/目录，不赋予项目SE实例全局权限。原件保留本地/server，正式回退产物与失败日志按SHA登记；回退不能删除事件、强推或恢复整库丢弃其他项目写入。

验收覆盖真实HTTP正反例、跨项目拒绝、旧范围/输入、丢回执幂等、阻塞与资源保护、逐项评审、Git隔离与路径、回退冲突/失败/权限/恢复、执行进程和临时目录清理、桌面手机浅深色及server一致性备份/实际源码回滚/重启读回。操作手册、模板、标准库客户端和角色brief同步。
