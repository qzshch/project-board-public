# 阶段目标与功能树

本轮仅实现通用阶段管理和产品功能树。优先级不等于依赖：聚焦阶段影响排序和交付核对，不禁止其他阶段无真实前置、且已获授权的任务领取、提交或按原规则验收。

## 阶段目标

SE 冻结目标、纳入与排除范围、优先级、精确交付基线、关联任务及其要求状态、逐项产品验收条件。阶段不会因为关联任务都完成就自动通过；SE 对固定版本与实际场景逐项核对证据，保留当前和历史结论。

阶段先后可以给出交付验收前置，但只约束该阶段的验收，不自动写入任务硬依赖。Worker 能否领取仍由真实任务依赖、接口、权限、写路径、资源与原门禁判断。已有高优先级任务保留其优先级；相同优先级下优先推荐当前聚焦阶段。候选先提交的流程保持。

历史里程碑提供既有证据入口，不自动迁移为当前产品阶段已通过。固定基线通过与“当前主线是否仍覆盖本次验证”分开展示；提交存在或祖先关系不能替代后续修改的验证。

## 功能树

产品 → 功能域 → 子功能 → 现有模块/原子任务。工程分类与技术方案继续保留。组织树只保存稳定 ID 的关联，任务状态、范围、验收和接口仍读原账本；整理树不会更改任务 ID、scope、资产锁、依赖或模块审批。

树版本不可覆盖，禁止成环、悬空父节点及重复主归属。没有完成分类的模块和任务明确显示在“待归类”，不因过滤消失。已有项目没有组织树时可按原模块父子关系阅读；技术方案与历史始终可查。

## 两项验收边界

1. 阶段聚焦只调整推荐，不阻止独立扩展任务认领；真实前置和原门禁继续拦截。阶段验收须匹配固定版本、任务成果与逐项证据；历史通过不冒充当前通过。
2. 功能树完整呈现多层级和未归类对象；整理前后既有任务 ID、范围哈希、历史验收及模块审批保持，跨项目与低权限写入拒绝。

示例项目作为实战：按玩家功能组织战斗、养成、剧情、心纸居、背包、邮件、活动及工程支撑；MVP 只登记为待核定/待验证目标，不补造游戏可玩结论，不重跑设备或修改游戏工程。

## 面板操作

项目概览首先显示当前交付目标、固定基线、尚缺条件及实际检验状态。“框架与规划”提供阶段目标和功能树；原技术规划、工程里程碑与全部历史版本保留在下方折叠区。任务详情与 brief 同时显示产品归属和阶段推荐，不改变认领规则。

SE 使用“新增阶段目标”填写字段、关联既有任务并分别选择成果验收/合入/实际运行要求；尚不明确的任务或基线可暂留空，状态会明确标记未就绪。新增阶段版本不会擅自替换原聚焦，SE 通过“调整当前聚焦”明确选择。每次阶段核对逐项选择实际结果并附原件引用，不能只点一个完成勾选。

功能树编辑为稳定ID、名称、父节点、范围和现有模块/任务关联。模块关联自动带出该模块的任务，零散/历史任务可以单独归类。任务只有一个主归属以免汇总重复，树内状态直接读取任务原记录。未分类对象始终单列；搜索功能或任务会展开相应路径。

## API 与模板

GET `/api/projects/<project>/roadmap` 返回当前阶段版本、聚焦、逐项就绪状态、固定基线与当前仓库主线、功能树和未归类对象。仅在已授权项目读取。

POST 项目 `/governance` 沿原 request_id/expected_revision 封装，新增 action：

- `stage_plan`：不可覆盖的 id/version；title/goal/scope/non_goals/priority/input_anchor/repo/tasks/criteria/entry_stages/reviewer/reason。tasks 每项为 task 与 stage（accepted/merged/native_accepted）；criteria 每项 id/expected。input_anchor 使用 git:完整40位或 sha256:完整64位，暂未知可空，空基线不能通过阶段验收。
- `stage_focus`：ref/reason；空 ref 取消聚焦。只做推荐排序，不对任务新增条件门。
- `stage_review`：ref/scope/input_anchor/result/checks/summary/evidence；checks 必须逐项覆盖条件（id/result/summary）。指定审核者核对当前范围；Git版本实际读取仓库对象，并核对要求合入/运行的任务提交确实包含在目标中。实际场景是否达成仍由SE按证据判断。阶段验收前置 entry_stages 只约束阶段结论，不约束任务领取。
- `function_tree`：version/nodes/reason；node 为 id/title/description/parent/module_ids/task_ids。关联本项目稳定模块ID，不抄写技术版本及任务范围。组织版本保留历史。

公开模板：`/templates/stage-plan.json`、`stage-focus.json`、`stage-review.json`、`function-tree.json`。使用前替换项目SE与真实输入，不把示例当作验收事实。

任务显式P0/P1等优先级始终先比较，相同优先级再优先聚焦阶段。所有任务的原真实依赖、接口冻结、写路径和排他资源检查不变。阶段范围或任务成果改变时重新核对该阶段；单纯调整组织树、更新说明性note不让旧任务验收或阶段结论全量失效。
