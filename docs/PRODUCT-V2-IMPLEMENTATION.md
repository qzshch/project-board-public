# 工作空间 v2 实施边界

用户于 2026-11-16 批准 design/product-workspace-v2 的完整设计进入开发。
原型的演示数据不进入生产状态。保留现有项目、任务、事件、权限和证据门禁。

本轮包含：需求与变更、独立缺陷池、项目 Token 账本、商用密集界面与
43 组旧能力承接、大项目分层依赖图、项目级 Git 只读接入、Agent 原生会话检索。
不包含经营治理、计费、外部聊天平台或业务项目的代码修改。

固定接口如下，均为增量接口，项目路径先授权再读取或写入：

* product-model@1：复用 intake 稳定 ID；已确认定义不可覆盖，变更核对旧版本；
  需求业务达成和缺陷精确输入复测独立于任务完成；旧接口不能绕过采用后的门禁。
* project-usage@1：项目独立追加账本、稳定样本 ID、流式修订与累计差值；
  缓存/推理为子集，不重复相加，未知保留 null；区分实测、手填和估算。
* workspace-v2@1：旧字段和动作继续可达；图在授权项目内聚合，不截断总任务；
  需求、缺陷、时间、代码、任务和会话之间保留可追溯关联。
* repository-onboarding@1：SE 发起项目仓库请求；server 生成专属只读密钥；
  GitHub 授权经外部核验后才允许镜像同步；不暴露实例密钥或允许任意命令。
* project-sessions@1：原生 Session ID 与绑定、尝试、传输 ID 分开；保存运行时、
  机器、角色、任务、接续关系；手工记录不构成托管/控制证明，未知不伪造。

共享入口由本会话单写者实现。验收分别检查以上七组要求及既有权限/门禁回归。
操作手册同步更新，独立 fixture 完成后部署 server；旧源码回退只读，保持新历史。
同一控制器使用不同审核身份，不能声称人工或独立模型审核。
