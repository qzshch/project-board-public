# 治理、时间、质量与资产升级的交付边界

本轮按用户确认的五项完整实现并部署server，保留既有任务/事件ID、哈希链、项目权限和接口版本。API v2保持兼容，新增项目内operations schema 1；旧项目不自动伪造工时、测试或资产验证。

1. 分级治理：项目默认light/standard/strict；经理按当前任务范围评估风险，已知高风险自动抬升。轻量任务可免模块完整评审及重复证据；权限、资源、私有资产与共享接口约束保留。非代码可提交产物锚点。
2. 时间：版本化估算、明确作业/等待/暂停/结束、原因与返修标签、修订留痕、阶段/等待/返修/管理成本汇总、估算校准和硬依赖路径。未知历史投入不填零；自然历时与总投入分开。
3. 用例：不可变用例/测试套件版本、任务范围测试计划、手动和自动运行结果、覆盖关系、跳过/阻塞与失败保留、当前输入有效性门禁。
4. 自动化：经理发布套件，独立runner身份领取有租约/资源锁的队列，工作站本地批准套件摘要；固定Git输入、隔离导出、静默有限执行、退出码与逐用例结果、日志/产物真实SHA回传、取消/超时/重试和finally清理。服务端不执行命令。
5. 资产：候选/提炼/实际验证/登记私有版本/审核共享，以及消费反馈、接入成本、预估节省和弃用。验证版本与实际运行产物哈希关联。

共享接口：operations写请求为request_id/expected_revision/action/payload，单项目SQLite事务与任务写入串行。版本冲突重读后决定；请求重试幂等；追加事件带SHA链。执行器仅有本项目runner权限，不能领取开发任务或修改治理策略；测试套件、范围或输入变化后旧结果不可顶替新验证。项目经理为这些新增接口与变更影响负责人。

验收：隔离HTTP正反例、并发和幂等、真实执行器成功/失败/取消/超时/过期范围、可复跑失败证据、时间计算/未知值与分级反例、资产验证到共享闭环、桌面/手机浅深色、server一致性备份/源码回滚/重启、原始链与凭据保留、临时资源清理。不得在生产创建演练项目或触发其他项目业务测试。
