# 当前状态与最短交付收口

本轮仅补齐四项：实时权威来源、当前/历史分离、重复提醒收口、普通任务减负。保留既有任务、事件、身份、输入与验收门禁，不自动清除未决发现，不自动降低风险等级。

## 唯一维护位置

任务范围、候选、验收与合入各在原结构化记录维护；项目当前状态通过 `/api/projects/<project>/current` 从同一项目数据库读事务生成。资源文档、轮次总结和交接报告是参考或快照，不能覆盖实时记录，也不需要每轮重写一套状态表。

任务列表默认围绕当前执行记录，已完成与历史结构可切换查看。原始完整 snapshot、历史接口与任务直达地址保持。资源可显式标记 snapshot，默认作为历史资料查阅；不通过文件名猜测或改写原件。

## 提醒收口

工作台以任务汇总行动，另分等待执行者与未读通知。普通讨论沿原线程回复；确需新线程时，由 SE 明确指定同任务的当前接续线程并记录理由。旧讨论保留内容与接续链接，退出当前行动。阻塞、偏离和明确停止决定沿原核准流程处理，不能借替代讨论解除门禁。

## 普通任务最短路径

读取当前任务与 brief → 领取 → 按范围工作 → 一次提交候选（成果、工作记录、结论、证据、验证和剩余项）→ SE 复核。结构化声明、测试、独立审核等缺项作为验收准备项，不要求先获得 SE 审核才能提交候选。新输入仍须重新核验；不把普通提交视为验收或合入。

固定产物/运行与证据可被任务、验收、资产目录和交接视图引用，不反复抄写正文。原始日志留项目本地/server；只有需要独立排期的新问题才转入需求池，只有需要复用的成果才提炼为资产。

## 本轮验收

1. 当前接口项目隔离、单事务读回；资料不能冒充实时状态，旧记录可追溯。
2. 当前/完成/历史结构视图完整可切换，资源快照显式分类，权限和输入不改变。
3. 工作台按任务汇总；讨论替代有权限定、幂等回执和继承链，阻塞/停止不被绕过。
4. Worker 可直接提交真实候选，旧验收门禁继续生效；手册、桌面/手机浅深色与 server 发布读回通过。
