# 人类管理、跨端编排与有界委派

## 1. 本轮目标

本轮复用现有项目、任务、评论、候选、验收、基线、规则与接手包，只新增人类账号入口、已有项目接管诊断、跨机器会话编排、有界委派四组能力。正式公告板继续运行在 server；各电脑只运行本地接入端及自己的 Agent 系统，不建立 PC 公告板生产副本。

## 2. 人类管理入口

独立账号密码登录，凭据使用加盐派生摘要；一次性初始化入口保存在实例私有目录，不放公开手册或 Agent 提示。人类会话与项目 Agent 凭据、维护凭据区分，服务端依据认证来源判定，不根据 User-Agent、自报角色或界面标签判断。用户可查看所有项目与其资料，并管理机器接入；项目 Agent 继续按原项目鉴权。最高权限不把未知证据变成测试通过。

保留既有 Agent 身份、项目 ID、任务 ID 和事件链。初始化入口单次使用，失败登录限速，退出和改密使相应会话失效。公开帮助仍无需登录；普通 Agent 阅读登录说明不获得人类权限。

## 3. 已有项目接管

把历史材料、当前执行与未来规划分开：原清单先作为有来源的登记事实，只有已核实的当前范围才发布给 Worker；历史 DONE/PASS 不自动变成新验收，也不要求全部历史项目立即补齐实施门禁。

提供机器可读诊断和对应最短操作：缺背景、输入、边界、风险核定、模块决定、固定接口、前置成果、Git/执行环境及待评审分别报告。只能报告当前角色可见的本项目信息，不自动修改业务项目。重用现有规划草案和批准规则，不另造一套迁移审批。

客户端区分暂时不可达与业务拒绝：读取和携带冻结 request_id 的幂等写入可按有界退避重试 502/503/504；不能修改正文、版本或请求 ID，409 保持需要重新判断。会话创建、一次性入口等非幂等操作不得盲目重放。

## 4. 可扩展跨机器编排

任意 Tailscale 电脑都可安装接入端，经实例授权并在本机固定允许项目、工作根、运行时启动命令及并行上限。接入端主动连接 server，server 不要求能 SSH 登录每台电脑。加入 Tailscale 只证明网络可达，不授予对该机器运行命令的权限。

服务端只发送结构化会话动作，不发送 Shell、可执行路径、环境变量或任意 RPC。运行时命令和供应商凭据留在机器上。机器报告真实版本、握手能力及可用模型，未安装、未认证、失联或未通过探测时显示不可派发，不把模型名称写死为可用。

Codex 采用其 app-server 协议，Zcode 采用其自有 NDJSON 协议，DeepSeek Harness 采用官方 SDK/ACP 协议。适配器分别处理帧格式、创建、恢复、忙碌、取消、审批和完成事件，不能假设三者兼容。安装版本与实测结果是能力判断依据。

SE 将项目/任务/当前范围与接手包绑定到指定节点、运行时和模型，创建 Worker 会话。每个会话使用自己的项目凭据；同一会话不能改绑其他项目。恢复沿用原会话 ID、项目和机器工作根。复用已有会话须显式绑定并确认归属，不能自动接管用户正在运行的其他聊天。

Worker 评论或提交生成持久通知；SE 的回复/决定通知原 Worker。通知通过事件游标和稳定事件 ID 去重，保留待发送、已接收、失败、待恢复的区别。运行时确认接收不等于任务完成；任务仍由真实 submit/accept/merge/native 推进。没有绑定到运行时的 SE 仍在原工作台接收待办，不伪造“已唤醒”。

Worker 自主选择是否等待的规则继续生效。忙碌的运行时支持安全补充输入时才发送，否则保留队列等其空闲；不以重建会话代替恢复。SE 明确 stop 时对本接入端管理的目标会话发停止请求，确认状态后才登记停止，不按进程名杀其他程序。

每次传输有租约、固定操作 ID 和本机收据。准备、发送、等待及清理阶段持续续租。网络断开、回执丢失或进程退出不能当作成功；不能证明非幂等动作结果时进入待恢复，禁止自动重复创建或重复发模型输入。原始模型会话与日志留本机/server，面板记录受控引用和状态，不收供应商密钥。

## 5. SE 有界委派

研究执行、材料整理、测试运行、独立复核、吸收候选准备和任务草案可以交给 Worker。SE 按具体任务、scope/version、成果锚点、允许动作、执行者及期限授权；不通过全项目提升为 SE 达成委派。

普通 Worker 可以沿现有流程准备规划草案、研究和证据；发布新范围、改变公共接口和批准治理规则继续由有权负责人完成。委派的评审可逐项记录结论；明确允许的轻量/标准任务可委派验收与基线登记，仍经过原门禁、当前测试及实际 Git 核验。严格风险的最终批准、权限/持久化/生产/未知影响留在 SE/人类。实现者不能借委派验收自己成果；不同账号或声明不同模型均不证明实际独立。

授权过期、撤销、范围或成果改变立即阻止新特权操作，历史回执保留；重试同一已完成请求不重复执行。委派记录、使用记录和剩余工作可从任务详情查看。SE 保留撤回、返修和升级处理选项。

## 6. 验证与交付

测试包含人类全局读取与 Agent 跨项目拒绝、初始化与会话失效、既有项目诊断、三种协议的真实帧及故障、重复通知、掉线/重启/忙碌/未知结果、委派撤销/过期/锚点改变/自签拒绝。使用隔离 fixture，不往业务项目写演示任务或通过记录。已安装运行时的控制面实测与实际模型执行分别报告；未连接环境不计实机通过。

操作手册同步更新；源码与固定输入测试通过后才有界发布 server，验证备份、源码回退、重启及原链前缀。运行原件留本地/server，Git 只收源码、说明和测试代码。
