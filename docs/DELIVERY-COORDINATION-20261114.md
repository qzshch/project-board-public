# 第二批：需求、接续、评审、效率与外部核验冻结边界

基线27fe6013369311f4a787332e7a11984ecc5ff028。用户已批准核心及扩展完整开发、隔离验收、手册同步和server部署。接口拥有者为本项目SE；消费者为现有浏览器、标准库客户端、项目本地协作/观察工具。旧API2、治理2、operations1和workflow1兼容，新增coordination_schema1；数据增量保存在原operations追加事务，禁止重写四条历史链。

GET /api/projects/<p>/coordination[?task=ID]：按角色过滤的需求/来源、计划/检查点/评审批次、效率、门禁/观察及资源核验。GET /coordination/feed?cursor=<opaque>&limit=50：四链稳定游标、最多100条、有界扫描；项目身份先鉴权，资源管理/实例元数据不能泄漏。POST /operations复用冻结request_id/expected_revision/action/payload，消费游标属于本人，已送达/已读/已处理分开。网络丢回执重发原请求；409重读后决定，不盲目覆盖。

需求登记、分诊及来源链与执行硬依赖分开；只有SE批准的已有模块/任务链接能进入执行。实施计划固定任务scope/version、基线、验收计划及实际接口摘要；轻量任务无额外审批，standard由SE选择，strict涉及实际高风险步骤采用批准计划。审批失效只影响引用对象，旧版本保留。评审批次绑定真实Git base/target，行锚点来自实际差异；变更后标旧锚点，不自动挪行。增量阅读不能豁免最终精确输入验证。

检查点为声明，不冒充机器观测；接续提供最近检查点、后续任务/治理/操作/Git变化游标和显式复核条件。离线、游标推进或心跳过期不释放资源或自动启动外部Agent。WIP计数按原ACTIVE集合，等待仍占有任务；模块软提示或硬门禁由SE设置。效率区分历时、实际申报工时、排队、返修与未知；根因由SE核定，改进链接用例/任务/资产后展示证据，不自动共享。

外部条件门固定范围、阶段、精确输入、来源、检查名/PR、有效期；项目本机批准观察器读取GitHub固定仓库API或本机批准路径，不接收网页命令/路径。human表示授权Actor确认，不证明自然人；timer满足时间条件不等于成果验收；CI只满足对应门，后续状态/提交变化和过期使其失效。观察器角色runner另获SE固定kind/target授权，本机另批准具体配置和摘要。文件/清单核验不上传原件；资源可见范围、版本及摘要过滤与原目录一致，旧观察不能覆盖新版入口。目录清单逐项有界核对，不追随链接、不读取凭据路径。独立observer-kit和协作客户端不包含任何实际配置/身份。

验收：真实HTTP完整需求→分诊→任务/计划→阻塞→检查点接续→差异评审→测试→根因改进链，重复/旧范围/失联/越权/跨项目/资源私有/错误CI和SHA反例；本地观察器真实文件及GitHub协议替身；桌面/手机浅深色实渲染；server固定输入回归、一致性备份、源码回滚、重启读回、既有链与身份保持。生产不建立演练记录。正式证据留G/server、源码边界检查后私有提交。
