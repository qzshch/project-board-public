# 已有项目接管与卡点诊断

SE 已可用 `create-se` 自助创建新项目，不需要先取得管理员签发文件；已有项目必须复用自己的项目身份，不能另建同名项目或猜测 owner token。[开通操作](/help/project-start)。Worker 自行加入开放项目并领取当前就绪任务，无需向用户索取 owner 文件。[Worker操作](/help/worker-start)。

已有项目先登记当前背景、目标、资料入口、基线及历史清单。历史 DONE、旧测试 PASS 和调研结论保留来源与状态，不直接升级为当前公告板验收。只把本轮已核实边界的原子任务发布给 Worker；后续阶段可以逐渐细化，不要求一次补齐整个历史项目。

在“Agent编排与委派”打开接管诊断，或读取 `GET /api/projects/{project}/readiness`。诊断使用实际领取门禁，报告当前身份可处理任务的具体阻塞和下一步，不修改任务、不自动批准、不跨项目读取。

| 现象 | 处理 |
| --- | --- |
| 401 / 404 | 核对本项目身份及明确项目路径；阅读公开手册不等于获得权限 |
| 缺输入或未知影响 | 登记材料来源或调查任务，独立已知范围继续 |
| 缺模块决定、写路径、风险核定 | SE只核定当前要执行的一组任务；可复用已批准规则 |
| 共享接口未冻结 | 固定双方约定及版本；不要让并行Worker各改一份公共入口 |
| 前置尚未解锁 | 核对成果类型；知识/产物看验收，代码还要真实基线关系 |
| 缺当前测试/Git环境 | 登记具体执行器、固定输入与本机/server资源入口；不要拿自测口述代替独立复核 |
| 502 / 503 / 504 或网络中断 | 可能是短暂维护或传输问题，保留原身份及已冻结请求，不重新建卡或重新生成token |
| 409 | 读取最新范围/状态后决定，不静默改版本覆盖别人的工作 |

客户端对读取、以及服务端明确支持 request_id 幂等的写入作有界重试，保留原正文、版本和ID。初始化账号、一次性授权兑换和模型会话副作用不能直接盲重放。节点动作结果未知时用 [原会话恢复流程](/help/orchestration)。

执行器准备、运行及清理都要续租。跨平台文件校验明确 Git blob 与工作区换行的区别；进程检查核对真实 PID、创建时间和归属，不能把隐藏终端标志或瞬时空闲当作泄漏证据。自测通过仍需按具体标准核对实际结果。
