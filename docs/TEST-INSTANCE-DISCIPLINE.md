# 项目纪律：测试实例与并发隔离

适用于同项目多SE、多Worker、多测试执行器并发。SE在项目章程 constraints 中采用本纪律，
并把具体实例清单登记在项目资产；Worker先读任务brief中的固定入口与占用要求。

## SE负责登记与分配

为可分配测试实例建立稳定ID，建议 `机器/类型/实例`，如 `node-a/android/mumu-01`、
`node-b/browser/cdp-02`。资产入口登记机器、实例ID、连接方式、用途、环境版本、管理者、
可授权使用者、隔离范围、保留/清理规则和状态记录位置。只放受控引用，不放密码、令牌或账号秘密。
同一物理实例的别名必须归一到同一个排他资源ID，不能换个CDP URL就当新实例。

实例清单最少记录：实例ID、机器、类型、环境/快照、连接入口、当前使用者、任务/尝试、
预约/占用/待恢复/空闲状态、开始及最后确认时间、关联账号/端口/数据资源、交接与清理责任。
清单可以是项目自己的Git外JSON、表格或工具登记，不要求每个项目采用相同环境管理器。

## 使用者测试前核对

1. 明确使用哪个实例及授权。已有浏览器CDP、安卓模拟器、真机等不能因“可连接”就任意占用。
2. 核对隔离边界：浏览器进程、profile/user-data-dir、CDP端口、下载/产物目录；
   安卓实例/ADB serial、ADB服务端口、账号、存档/快照；以及后端服务、数据库、工作目录、
   网络端口、测试账号和配额。不同实例仍可能争用同一账号或后端。
3. 把冲突资源的同一稳定ID填入任务work.resources及用例/套件resources。
   任务领取和自动化运行继续使用已有原子排他门禁；测试执行器还需核对本机真实占用。
   管理清单只是协作记录，不构成OS锁；手工测试和不同公告板项目也不能假设会被平台自动互斥。
4. 需要增加实例时，按项目授权自行创建，记录真实进程PID、创建时间、命令身份、实例入口和用途。
   不随意关闭、重启、清理其他Agent或用户的实例。

## 释放与恢复

测试结果带实例ID、环境/快照、真实输入、实际用例和证据入口。自己的临时进程、账号会话、
端口、profile、测试数据和产物按项目规则finally清理或归档；长期保留实例恢复约定快照并标空闲。
任务未结束但暂时不测试时，可在SE确认范围和现有资源门禁后换用独立测试任务或计划，
不能单方面从活动任务删资源让别人竞争。共享设备、账号或持久数据变更先取得对应拥有者确认。

心跳丢失、会话中断或超时先标“待恢复”。接手者核对原进程、ADB/CDP入口、任务/运行租约、
账号、数据和证据是否仍在使用，取得SE/实例管理者确认后恢复。不能只凭瞬时空闲或租约到期强抢实例。
发现竞争或污染时记录阻塞评论，说明受影响运行和失效证据，暂停相关测试并隔离重跑。

## 渐进采用

轻量项目至少说明“使用哪个实例、谁在用、怎么连接、怎么释放”；并行或共享环境补全关联资源。
复杂环境的实例创建、快照和调度由项目SE/Worker选择合适工具，并把入口与纪律登记到公告板。
本轮提供纪律与现有资源门禁的接法，不宣称平台已实现通用模拟器/CDP调度和跨项目自动锁。
