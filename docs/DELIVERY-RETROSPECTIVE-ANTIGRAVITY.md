# 事后整理与 Antigravity 编排：实施边界

本轮仅补齐两个用户已批准的入口：按项目事后整理用量、工时和归档证据；在现有节点编排中增加 Antigravity CLI 的 SE/Worker 适配。沿用项目身份、任务ID、原验收、持久通知和保守恢复。

## 固定边界

- Antigravity 使用官方 `agy acp`，协议版本1。以 `session/new` 返回的原生 sessionId 为准，恢复同一会话，忙碌时排队，取消仅限自己持有的会话。模型必须来自实际能力发现并经本机允许。不会安装/登录新账号、启用跳过权限或访问其他项目会话。
- 事后整理是可选批次：Worker列出本项目历史会话、时间段、原件位置/SHA与缺失项，形成草案；SE逐批确认。原件继续留本地/server，面板保存元数据和统一入口。历史申报和现场采集分别标识，未知不填零。
- Token沿用原账本，累计量保持同一会话、计数流与次序；重复或重叠的来源必须先处理，不能把相同历史再累计一次。工时不得从会话历时推断，审核补录保留依据与版本，不覆盖旧时段。不借补录自动宣布整个任务工时完整。
- 不增加预算门禁、计价模型、自动选模、全账号聊天扫描、普通任务必填要求或自动文件搬迁/删除。

## 验收

1. 实际安装的 CLI 完成协议握手、模型选择、新建与同ID恢复；独立fixture验证SE/Worker、消息/交付通知、忙碌/异常/取消和跨项目拒绝。CLI接收或结束一个turn不等于任务验收通过。
2. Worker可以提交整理草案，SE核对后才入统计；重复提交/审核幂等，冲突与跨项目输入被拒绝，历史范围和缺失明确可见。
3. 项目归档入口可由接手Agent找到，原件及身份不进入源码；操作手册、下载工具包和页面入口同步。
4. 独立状态测试、完整回归、实际界面及server有界发布/重启/回退验证。实际记录在Git外证据目录，本文不冒充运行回执。
