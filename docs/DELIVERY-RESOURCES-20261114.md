# 项目资源目录交付边界

缓存、调研、美术、归档、测试记录、日志、运行态及交接资料统一出现在项目资产页。原件留在本地或server，Git只保留产品代码、模板和操作说明。

冻结接口 resource-directory@1：项目内 GET /resources（分类、来源、任务、关键词、历史状态和有界分页）、GET /resources/{id}、GET /resources/{id}/history；治理动作 resource_register/resource_update/resource_retire 复用既有 request_id/expected_revision/action/payload 事务和哈希链。更新及停用另校验 expected_version，错误400/403/404/409。UTC秒，SHA256小写64位。API2、治理2、operations1保持兼容，新增目录schema1。

登记标题、分类、用途、维护者、可见范围、位置/所属机器/访问条件、内容版本、动态性、摘要及覆盖对象、可用性、保留规则、关联任务/模块/资产版本和接手注意事项。元数据版本不等于内容版本；动态目录不编造固定摘要，固定内容要求实际文件或清单摘要。登记不读取、上传、删除原件或赋予文件权限。既有项目材料和入口自动保留为待分类项；既有自动化完成回执自动投影记录及产物，明确文件现状未知、历史任务范围不能替代当前验证。

项目成员、管理角色、实例管理员三层可见范围覆盖列表、搜索、导出、详情、历史和任务brief。实例资料使用operator-专用ID，不能降级公开；不登记密钥、私有身份目录或管理员会话入口。停用只停止推荐，不删除原件。项目级目录变化使SE交接范围失效；实例独有资料不随项目SE交接。

验证真实HTTP权限和反例、幂等/冲突/历史、交接范围、自动运行投影、现有知识继承、Web表单/筛选/项目切换及桌面手机浅深色。部署server前一致性备份，实做回滚和重启读回；只登记实际资料，不建立演练数据，也不猜测其他业务项目的美术或缓存路径。
