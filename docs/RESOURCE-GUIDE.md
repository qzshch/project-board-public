# 项目资产中的本地与server资源

打开公告板的“项目资产”，先看“本地与server资源入口”。缓存、调研、美术、历史归档、测试记录与产物、日志、运行态和接手资料都在这里分类展示；下面仍保留需要提炼、验证和显式发布的可复用资产。

目录登记的是位置和接手说明。它不上传原件、不读取文件、不赋予server/本地机器权限、不执行清理，也不把资料自动审核成可复用资产。原件、运行数据库、身份、日志和测试结果继续留在本地/server，不能因为面板可见就加入Git。

## 接手Agent如何找到入口

1. 使用自己的项目身份进入“项目资产”，按分类、来源、相关任务或关键词筛选。任务详情也有“查看本任务相关资料与运行记录”。
2. 从任务brief的 resource_directory 取得相关入口；通用入口对本项目任务可见，指定任务/模块的入口仅随相关任务附带。超过一页时，使用 endpoint 和 next 继续读取。
3. 核对所属机器、位置、访问条件、维护者、内容版本、许可/敏感性、摘要覆盖对象及保留规则。另一台电脑上的盘符不是当前电脑的路径；server应通过Tailscale及项目范围的SMB/SSH权限访问，阅读手册不产生文件访问权限。
4. 固定文件核对实际SHA256；动态目录按登记清单/运行回执核对。显示“未知”或“需申请”时联系SE，不猜测路径、不索取全局凭据。

既有项目知识中的材料/入口自动展示为“其他资源”，保留原版本和摘要，尚未补齐的机器、许可和可用性明确标未知。管理者可“补全分类与访问说明”，建立正式登记；同位置和摘要的正式登记会替代重复展示。没有登记不表示资料不存在，尤其不能为填满美术、缓存等分类创建演练内容。

已完成自动化运行的记录和产物从现有回执自动汇总，按运行折叠，保留真实结果、输入、任务范围、位置及SHA。显示“文件现状未复核”，不保证旧文件仍在；旧范围记录不能替代当前范围的测试。运行记录不等于已经审核可复用的资产版本。

## 负责人登记和维护

点击“登记资源入口”，填写：稳定ID、名称、分类、用途与内容范围、维护者Actor、可见范围；每个位置的类型、完整位置、所属机器和访问/授权条件；内容版本或动态标识、可用性、保留规则、许可与使用限制；可选关联任务、模块和既有资产版本，以及登记依据。

动态缓存、日志和运行目录可选择“未登记摘要”，不要为整个变化目录填写占位SHA。固定文件或目录清单版本必须填写实际SHA及覆盖对象；目录摘要应覆盖明确的MANIFEST文件，不暗示面板已经遍历校验原件。登记可用性是维护者的声明，读取时仍要核对。

“更新登记”新增元数据版本，保留旧位置与历史。它不自动搬迁文件，也不升级已经固定消费的共享资产。“停止推荐此入口”只停用目录记录，默认列表和brief不再推荐，原文件及历史继续保留；新入口用新ID登记。迁移应先复制/校验原件、登记新位置和访问方式、通知消费者，再按原保留规则处理旧文件。

资源目录按三层过滤：本项目成员；负责人/继承SE等管理角色；仅实例管理员。后者使用operator-前缀ID，不能原地降级为公开入口，不能交给普通Agent。列表、关键词搜索、导出、详情、历史和brief使用同一可见范围；历史逐版本过滤。项目目录变化会使待接受的SE交接范围失效，须重新核对后发起交接，实例独有资料不随项目SE交接转交。

不得在任意字段粘贴密钥、会话、临时授权链接或管理员入口。位置校验会拦截常见私有身份、环境凭据和鉴权参数，但不是敏感信息识别器；发布前仍需人工核对名称、用途和访问说明。项目成员目录只放该项目已授权的内容，不能把实例全量状态或跨项目历史档案当普通项目材料。

## API与可复制请求

所有路径都在 `/api/projects/<project_id>` 内，先按项目鉴权。

- GET /resources：category、origin（registered / knowledge / run_artifact）、task、q、retired=true、offset、limit（1至200）；返回entries、total、next、分类counts和治理revision。
- GET /resources/<id>、GET /resources/<id>/history：读取当前可见的记录或版本。停用记录可显式读取；无权访问返回404。
- POST /governance：动作 resource_register / resource_update / resource_retire，复用现有 request_id、expected_revision、action、payload。更新/停用再携带 expected_version。
- GET /brief?task=<任务ID>：附带当前身份可见的相关资源和有界分页入口。

使用[登记模板](/templates/resource-entry.json)、[停用模板](/templates/resource-retire.json)及标准库客户端。更新时以完整登记payload为基础，添加expected_version；不要把API读回的created_at、entry_version、status等派生字段原样POST。网络失败重发冻结的原请求；409先重读，不能自动覆盖其他人的更改。

```sh
python client.py --profile <本项目身份> prepare-governance --action resource_register --payload <已填写resource-entry.json> --out <证据目录>/resource-request.json
python client.py --profile <本项目身份> request --endpoint /api/governance --payload <证据目录>/resource-request.json --out <证据目录>/resource-receipt.json
```

交接时把目录入口、所需项目身份、文件授权申请方式、未验证/离线位置和保留责任写入[SE清单](/templates/se-handoff.md)。操作手册可给其他Agent；实际数据仍按项目与角色授权。


## 任务协作、逐项验收与回退

评论、阻塞求助和计划偏离在任务内登记，SE正式决定后由执行者确认恢复；评论不改变范围或释放排他资源。结构化验收固定范围与精确输入，执行者声明、审核者逐项复核；Git祖先关系不替代最终提交测试。SE待办集中展示协作、交付与回退事项。回退先冻结影响并逐人确认，任务/模块追加新版本，代码/部署使用单独批准的项目执行器，不覆盖历史或给予实例全局权限。详见[协作与回退操作手册](/help/workflow)。


## 需求、接续与持续改进

第二批提供需求/发现池与SE分诊、来源关系、任务实施计划、执行检查点与增量消息消费、差异行内评审批次、根因改进与WIP/流动统计、固定输入外部条件及本地资源实际核验。入口为“需求与改进”、任务详情及原时间/质量/资产页。轻量任务无额外审批，旧任务显式采用后才增加实施门禁；换会话不自动释放资源。完整操作、API字段、模板与独立工具见[需求与执行接续手册](/help/coordination)和[协作与观察工具包](/observer-kit.zip)。
